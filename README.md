# Gator

Boot.dev learning project built with Go and PostgreSQL. PostgreSQL runs in Docker; Goose and sqlc run in your terminal.

## 1. Install the tools

You need Docker running and Go compatible with `go.mod` (currently Go 1.27.1).

Install Goose for database migrations and sqlc for generating Go code from SQL:

```sh
go install github.com/pressly/goose/v3/cmd/goose@latest
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
```

Make sure your Go binaries are on your PATH. For the default Go install location:

```sh
export PATH="$(go env GOPATH)/bin:$PATH"
```

Add that line to `~/.zshrc` to keep it for new terminal sessions.

```sh
goose -version
sqlc version
```

Run the remaining terminal commands from the project root:

```sh
cd /Users/cjvnjde/projects/bootdev/gator
go mod download
```

## 2. Start PostgreSQL in Docker

Create the container once:

```sh
docker run -d \
  --name pg \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 \
  -v pgdata:/var/lib/postgresql \
  postgres:18
```

This uses container `pg`, volume `pgdata`, and port `5432`. The database username and password are both `postgres` for this local learning setup.

For PostgreSQL 18, mount the volume at `/var/lib/postgresql`, as shown in the [Docker PostgreSQL guide](https://docs.docker.com/guides/postgresql/).

If the container already exists, start it instead of running `docker run` again:

```sh
docker start pg
```

Check that PostgreSQL is ready before continuing:

```sh
docker exec pg pg_isready -U postgres
```

Wait until it reports `accepting connections`. To inspect startup logs:

```sh
docker logs pg
```

To stop it when you are done:

```sh
docker stop pg
```

The `pgdata` volume keeps the database between stops and starts.

## 3. Create the database

Run this once, after PostgreSQL is ready. Skip it if `gator` already exists:

```sh
docker exec pg psql -U postgres -d postgres -c 'CREATE DATABASE gator;'
```

Open a SQL shell inside the container:

```sh
docker exec -it pg psql -U postgres -d gator
```

Useful commands inside that shell:

```sql
SELECT current_database();
\dt
\q
```

`\dt` lists tables (none yet before migrations), and `\q` exits. A separate local PostgreSQL installation is not required.

If you already have `psql` installed locally, you can also connect with:

```sh
psql "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable"
```

## 4. Configure Gator

Create or update `~/.gatorconfig.json` with:

```json
{
  "db_url": "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable",
  "current_user_name": ""
}
```

If you already have this file, update `db_url` and keep your existing `current_user_name`. The app reads this file from your home directory. `sslmode=disable` is for the local Docker database.

## 5. Run migrations with Goose

All commands below run from the project root. `-dir sql/schema` tells Goose where the migration files are.

Apply all pending migrations:

```sh
goose -dir sql/schema postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" up
```

Check migration status:

```sh
goose -dir sql/schema postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" status
```

Roll back the most recent migration:

```sh
goose -dir sql/schema postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" down
```

**The current `001_users.sql` down migration drops the `users` table and deletes its data.** Run `up` again to recreate the table.

Verify the tables:

```sh
docker exec pg psql -U postgres -d gator -c '\dt'
```

Alternatively, from inside `sql/schema`, omit `-dir sql/schema`:

```sh
cd sql/schema
goose postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" up
goose postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" down
goose postgres "postgres://postgres:postgres@localhost:5432/gator?sslmode=disable" up
cd ../..
```

## 6. Generate Go code from SQL

The existing `sqlc.yaml` connects these directories:

| Directory | Purpose |
| --- | --- |
| `sql/schema` | Database schema and Goose migrations |
| `sql/queries` | SQL queries used by the app |
| `internal/database` | Go code generated by sqlc |

After adding or changing SQL queries or schema files, run from the project root:

```sh
sqlc generate
```

Edit the SQL source files, then regenerate; do not edit the generated Go files directly. Goose changes the actual database schema. sqlc generates Go code and does not apply migrations.

## 7. Run the app

After configuring the app and applying migrations:

```sh
go run . register test1
go run . login test1
go run . users
```

Register a username only once. On later runs, start the existing container with `docker start pg`, apply any new migrations, and use `login` with an existing username.
